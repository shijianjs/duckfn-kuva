<dfk-features section-title="Built for statistical charts">

<dfk-feature icon="lucide:sigma" title="Statistical semantics, not just shapes">
The model is seaborn and ggplot2: you say what the figure means and the extension works out the axes, the bins, the scales and the layout — the part that makes a chart statistical rather than decorative.
</dfk-feature>

<dfk-feature icon="lucide:shapes" title="64 chart types, composable">
Scatter, histogram and box through violin, sankey, candlestick and heatmap. Overlay several series on one set of axes, or lay them out as a multi-panel figure with a shared legend and a second y-axis.
</dfk-feature>

<dfk-feature icon="lucide:braces" title="One function: JSON in, SVG out">
kuva_render is an ordinary DuckDB function: hand it a JSON chart spec and it returns a complete SVG document, with nothing to import and no host plotting library in the loop.
</dfk-feature>

<dfk-feature icon="lucide:monitor-down" title="The same chart on every platform">
One .duckdb_extension draws it in the CLI, a Python or R session, the JVM, or the browser (DuckDB-Wasm) — no matplotlib, no ggplot2, nothing to install on the host.
</dfk-feature>

<dfk-feature icon="lucide:play" title="Examples that run here">
Every example on this site runs in your browser through DuckDB-Wasm — click Run on the gallery or the function reference and see the real chart.
</dfk-feature>

<dfk-feature icon="lucide:package" title="Install in one line">
INSTALL duckfn_kuva FROM community; then LOAD duckfn_kuva; — signed builds matched to your DuckDB version and platform, so no -unsigned flag is needed.
</dfk-feature>

</dfk-features>

## Install once, then call it from SQL

The extension adds ordinary SQL functions, with nothing to import at the call site. Install it once (left), then hand any query's data to kuva_render and get an SVG chart back (right).

<div className={styles.codeGrid}>

```sql title="duckdb"
-- once per installation, then once per session
INSTALL duckfn_kuva FROM community;
LOAD duckfn_kuva;
```

<div className={styles.codeColumn}>

```sql title="duckdb"
SELECT kuva_render('{"series":[{"type":"scatter","data":[[1,2],[3,4],[5,3]]}]}');
-- an SVG document
SELECT kuva_render('{"series":[]}');
-- error: kuva_render: `series` must not be empty: a single-figure chart needs at least one series
```

The comments are what each call returns — the first is the SVG a chart renders to, the second is how a bad spec fails.
