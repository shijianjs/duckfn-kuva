# v0.3.0

Released 2026-10-19. Wraps **kuva 0.6.0** (up from 0.5.0).

[GitHub Release](https://github.com/shijianjs/duckfn-kuva/releases/tag/v0.3.0) ·
[Commits since v0.2.0](https://github.com/shijianjs/duckfn-kuva/compare/v0.2.0...v0.3.0)

## What changed

**New output backend.** `kuva_render_typst(json)` renders the same spec as Typst source — a `.typ`
document containing a CETZ vector drawing that you compile yourself with `typst compile`. It has no
options object and takes the same optional dataset argument as the other functions.

**Composites.** A new top-level `composite` object (`type: coverage` or `brick_pop`) draws a
genome-browser coverage figure or a population allele-frequency figure. It is mutually exclusive with
`series` and `figure`, carries its own canvas size and does not read a dataset. See
[Composites](../reference/composites.md).

**Scatter.** Markers grew to ten shapes (`triangle_down`, `star`, `pentagon`, `hexagon` added), `trend`
learned `loess` (with `span`, 0.05–1), and points can carry their own `labels` with a shared
`label_style`. Label placement moved to the shared series schema, so `scatter`, `volcano` and `manhattan`
all support `repel` the same way.

**Histogram.** `step`, `cumulative`, `bin_method` (`sturges` / `scott` / `freedman_diaconis`, alias `fd`),
`weights`, and `groups` with stacking.

**Smaller additions.** `survival` gained `risk_table`, `median_lines` and `logrank_pvalue` (the log-rank
test is computed for you); `strip` gained `horizontal`; `brick` gained CIGAR ribbons (`cigars`, `dedup`,
`run_bracket`, `colors`), `sort` (`none` / `cigar` / custom row order) and vertical `marker_lines`;
`font.tick_family` and fifteen LTC palettes were added.

**New function.** `kuva_version()` returns the kuva version the loaded build was compiled against.

## Breaking changes

- **STRIGAR syntax.** kuva 0.6 no longer accepts the old `|` / `@` form. Strings are now `<count><letter>`
  runs, back to back, with letters mapped bijectively to base-26 (`10A5B`). The extension turns
  `strigar_issues` / `cigar_issues` into errors that name the offending row instead of drawing something
  wrong.

Everything else is additive: a spec written for 0.2.0 keeps working, apart from the STRIGAR strings.
