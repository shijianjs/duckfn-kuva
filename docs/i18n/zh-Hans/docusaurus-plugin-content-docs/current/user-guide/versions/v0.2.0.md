# v0.2.0

发布于 2026-10-13。仍然链接 **kuva 0.5.0** —— 这一版改的是 SQL 接口与 SDK，不是图型。

[GitHub Release](https://github.com/shijianjs/duckfn-kuva/releases/tag/v0.2.0) ·
[自 v0.1.0 以来的提交](https://github.com/shijianjs/duckfn-kuva/compare/v0.1.0...v0.2.0)

## 改了什么

**每个函数都多了一个第二参数。** 渲染函数现在还可以接受一个 JSON 对象，把数据集名映射到行数组 ——
于是图表的**配置**和**数据**可以由不同的东西构造：配置来自宿主 SDK，数据来自 SQL。系列用 `dataset`
挑数据集、用 `encode` 把列接过来；单参数写法完全没变。

```sql
SELECT kuva_render(
  '{"series":[{"type":"scatter","dataset":"sales","encode":{"x":"revenue","y":"profit"}}]}',
  to_json({'sales': array_agg({'revenue': revenue, 'profit': profit})})
) FROM sales;
```

**JSON Schema，由 Rust 类型生成。** `sdk/json_schema/` 下的 schema 是从解析规格的那批结构体渲染出来的，
所以不会和实现走偏。

**SDK。** TypeScript 类型从这份 schema 生成（`sdk/ts/`）；Java（`sdk/java/`）与 Kotlin Multiplatform
（`sdk/kotlin/`，含 Android）的模型从它的 OpenAPI 3.1 包装生成。每套 SDK 都有一条集成测试：加载真实的
Release 产物、通过它渲染一张图。

**文档。** 图库按类别重新分组，开发笔记迁进了文档站。

## 破坏性变更

- **行一律是对象。** `[x, y]` 位置写法被移除：`data` 的每一项都要写明字段（`{"x": 1, "y": 2}`）。
- **自定义值也对象化。** 内联的 `palette` 颜色、`labels`、`brick` 条目原本可以是裸值，现在统一成对象，
  与旁边的具名写法保持一致。

为 0.1.0 写的规格只要用的是对象行和具名选项，就仍然可用。
